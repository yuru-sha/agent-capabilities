# Topology, availability, and recovery

Distinguish RDS Multi-AZ instance/cluster patterns, Aurora topology, read replicas, and cross-Region replicas by their failover and read-scaling semantics.

Define backup retention, PITR, snapshots, copy/restore ownership, encryption, and recovery validation.

Replicas are not automatically a complete disaster-recovery strategy; include promotion, application endpoint changes, replication lag, and data-loss expectations.

Run restore/failover exercises against representative application behavior.
